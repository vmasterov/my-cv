Technically, the app uses an extended finite state machine (EFSM). On top of the modes, it keeps variables: the workday boundaries, the start of the current segment, and a count of completed work segments. Transitions have guard conditions (you can start work only if the day isn't over yet), and the transitions themselves update the variables (the count goes up by one each time you start a break). Without variables, you'd have to multiply states: WORK_1, WORK_2…
